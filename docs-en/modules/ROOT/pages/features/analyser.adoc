The *Analyser* page serves as the central incoming-attack overview in TW Forge.
All imported and uploaded incoming attacks (Incs) are collected here and automatically evaluated.

== Display and Interpretation of Attacks

Each attack is interpreted by TW Forge based on a *maximum possible offensive size*.
This maximum offensive size is expressed using the metric "maximum axes" / "maximum light cavalry".

Based on this calculation, each attack is assigned a *threat rating*, which is visualised by colour:

* *Green* — very high suspicion of fake / confirmed fake
* *Yellow* — small to medium possible offensive
* *Orange* — medium-sized possible offensive
* *Red* — large possible offensive

== Factors in the Threat Rating

The rating of an attack is based on the following factors, among others:

* *Last nobling of the source village*
Recently nobled villages generally have less offensive potential.

* *Known loss of offensive troops*
Losses from previous battles are taken into account.

* *Attacks already dispatched or landed*
If an offensive has already been sent or landed, it cannot be counted twice.

These pieces of information are combined to provide the most realistic estimate of the maximum possible attack strength.
If an attack can be restricted by one of these factors, an explanation is shown in an info field indicating which information was used to assess the incoming.

== Configuring the Threat Rating Thresholds

The thresholds for the individual threat levels (*Green*, *Yellow*, *Orange*, *Red*) are freely configurable.
They can be adjusted under xref:../settings.adoc#attacks[Settings → Attacks] to match individual playing styles or preferences.

== Filtering and Sorting[[filtering]]

The attack overview offers extensive filter options for targeted evaluation of large numbers of Incs.

=== Filter by Label

* e.g. "Ram tab"
* Free text search within the Inc label

=== Filter by Origin or Target

* by *Player*
* by *Tribe*
* by *Coordinate*

=== Filter by Confirmed Inc Size

* Known, visible Inc sizes (when commands are visible)
* Filtering by small (green), medium (orange) and large (red)

=== Filter by TW Forge Calculated Maximum Size

* Filtering by small (green), medium (yellow), medium-large (orange) and large (red)

=== Filter by Travel Time / Unit Type

* e.g. Scouts / Rams

== Personal Attacks and Account Reference

Attacks can additionally be filtered by personal relevance:

* *Own*
Only attacks uploaded by the current user are shown.

* *Own Account*
All attacks affecting the currently selected account are shown.

These filters are particularly useful for personal tracking and coordination within larger tribes.

== Importing Incoming Attacks

In order for incoming attacks to appear in the table, they must be uploaded either by the user themselves or by another member of the tribe construct.
This is done via the *Import* sub-menu.

For this, an SOS request must be created and then imported into TW Forge.
To create the SOS request, the "Incoming" view is opened in the game, the desired Incs are selected, and "Request Support" is clicked.

The complete text of the SOS request is then copied and pasted into TW Forge.

== Tabulator — Collaborative Defence Coordination

The *Tabulator* tab ("Attack Tabbing") is a collaborative tool for coordinating defensive support across tribe members.

=== Overview

A SOS request (in the same format as for the Analyser import) is pasted in to create a Tabulator request.
The incoming attacks to be covered are reviewed, participants (tribe members) are invited, and each participant selects the villages from which they will contribute defensive troops.
After a confirmation step, results are displayed showing the computed defence distribution per attack target and per participant.

=== Workflow

The Tabulator follows a guided multi-step process:

. *Attacks* — The SOS request is pasted in; incoming attacks are displayed with target, unit type, arrival time, and a live countdown.
. *Participants* — Tribe members are invited to participate in the tabbing session.
. *Settings* — Global settings for the coordination are configured.
. *Troops* — Each participant selects which of their villages they will contribute defence troops from.
. *Personal Settings* — Each participant adjusts their individual preferences.
. *Overview* — A confirmation summary is shown before finalising.
. *Result* — The computed defence distribution is displayed for each attack target and participant.

=== Usage Notes

* A valid SOS request must be available before a Tabulator session can be started.
* Each invited participant must complete the troop-selection step independently.
* Results are computed automatically once all participants have confirmed.
